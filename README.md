# Customer Churn Prediction

Full-stack churn prediction system built for the Nexoraa Technosolve ML internship assignment.

## Overview

Predicts whether a telecom customer is likely to churn, using the [Telco Customer Churn dataset](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) (7,043 customers, 21 features).

## Project Structure

```
churn_project/
├── churn_prediction.ipynb   # EDA, cleaning, model training & comparison
├── main.py                  # FastAPI prediction service
├── app.py                   # Streamlit dashboard
├── requirements.txt
├── churn_model.pkl          # Trained model (generated by the notebook)
├── scaler.pkl                # Fitted StandardScaler (generated by the notebook)
├── model_columns.pkl         # Expected feature columns (generated by the notebook)
└── WA_Fn-UseC_-Telco-Customer-Churn.csv
```

## Results

Three models were trained and compared: Logistic Regression, Random Forest, and Gradient Boosting.

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Random Forest | 0.806 | 0.669 | 0.535 | 0.594 | **0.844** |
| Logistic Regression | 0.806 | 0.659 | 0.559 | 0.605 | 0.842 |
| Gradient Boosting | 0.797 | 0.651 | 0.508 | 0.571 | 0.838 |

**Random Forest** was selected as the best model based on ROC-AUC (the dataset is imbalanced — ~27% churn — so ROC-AUC is a more reliable comparison metric than raw accuracy).

Top churn drivers identified: tenure, contract type, monthly charges, internet service type.

## How to Run

**1. Notebook**
```
pip install pandas numpy matplotlib seaborn scikit-learn joblib jupyter
jupyter notebook churn_prediction.ipynb
```
Run all cells. This generates `churn_model.pkl`, `scaler.pkl`, and `model_columns.pkl`, required by the API and dashboard below.

**2. API**
```
pip install -r requirements.txt
uvicorn main:app --reload
```
Visit `http://127.0.0.1:8000/docs` to test the `/predict` endpoint interactively.

**3. Dashboard**
```
streamlit run app.py
```
Opens in your browser. Fill in customer details and click "Predict Churn Risk" to see the churn probability, top risk factors, and a retention suggestion.

## Future Work

The following were out of scope given the project timeline and are not implemented:

- **Hyperparameter tuning** (GridSearch/RandomizedSearch) — the current models use reasonable defaults; a tuned model would likely offer a modest additional performance gain
- **Docker containerization** — the app currently runs via `uvicorn`/`streamlit` directly; containerizing would standardize the deployment environment
- **Cloud deployment** — currently runs locally only
- **A learned recommendation engine** — the dashboard currently uses simple rule-based retention suggestions rather than a separately trained recommendation model
